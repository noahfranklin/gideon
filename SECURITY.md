# Security & Responsible Use

## Intended use

Gideon skills are for **authorized, defensive security work**. Use them only against:

- Systems **you own** or operate.
- Systems you have **explicit written authorization** to test — a signed penetration-testing engagement, a documented rules-of-engagement (RoE), a bug-bounty program whose scope explicitly includes the target, a Capture-the-Flag event, or a lab environment you control.

Testing computer systems without authorization is illegal in most jurisdictions (e.g. the U.S. Computer Fraud and Abuse Act and equivalents worldwide). You are solely responsible for staying within the law and your authorized scope.

## What these skills deliberately do NOT include

To keep this project useful for defense and safe to publish, the skills intentionally exclude:

- Ready-to-run weaponized exploits or malware.
- Tooling designed for mass/indiscriminate targeting of third parties.
- Techniques whose primary purpose is evading detection or defensive controls.
- Instructions for exfiltration, persistence, or destructive actions against systems you don't control.

They focus on **methodology, test design, detection signals, and remediation** — how to find and fix weaknesses in software.

## Reporting a vulnerability in this project

Found a problem in the skills themselves (bad advice, an unsafe snippet, a broken checklist)? Open a GitHub issue, or for sensitive reports email the maintainer listed on the GitHub profile. Please don't file exploit details for third-party products here.

## Responsible disclosure

When you find a real vulnerability during authorized testing, follow coordinated disclosure: report privately to the owner, give reasonable time to fix, and don't disclose publicly until a fix is available or the agreed window elapses.
